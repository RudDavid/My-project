# My_Project - Менеджер задач с историей

## Постановка задачи

Студенты и IT-специалисты ежедневно работают с множеством задач. Без удобного инструмента легко забыть о дедлайнах, потерять контекст выполненных дел и запутаться в приоритетах.

**Цель проекта:** разработать консольное приложение для управления задачами, которое:
- Позволяет создавать задачи с названием, описанием и дедлайном
- Отслеживает изменение статусов задач (Новая → В работе → На проверке → Выполнена)
- Автоматически уведомляет о просроченных задачах и задачах с близким дедлайном
- Ведёт полную историю всех изменений

## Используемый паттерн: Observer (Наблюдатель)

### Цель применения

Паттерн Observer позволяет реализовать механизм автоматического реагирования на изменения состояния объектов без жесткой привязки классов друг к другу.

### Какую проблему решает

Без паттерна пришлось бы в классе `TaskItem` напрямую вызывать методы логирования и проверки дедлайнов. Это создало бы жесткую связь между классами. При добавлении нового функционала (например, отправки уведомлений на email) потребовалось бы изменять код самой задачи.

**Решение через Observer:**
- **Издатель (Subject):** `TaskItem` — при изменении статуса уведомляет всех подписчиков через метод `NotifyObservers()`
- **Подписчики (Observers):**
  - `ActivityLogger` — записывает в консоль время и описание каждого изменения
  - `DeadlineNotifier` — проверяет дедлайн задачи и выводит предупреждения о просрочке или скором истечении срока

Такая архитектура позволяет добавлять новых подписчиков (email-уведомления, сохранение в файл) без изменения существующего кода.
